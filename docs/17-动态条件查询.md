# 17 · 动态条件查询（conditionsJson）

前后端统一约定：**前端列出全部可查字段**；默认 **GET** 列表（保留 **POST** 备用）；后端对每个实体属性同时支持 **扁平筛选** 与 **动态条件**，并按字段类型选择 SQL 比较方式。

## 核心契约

| 项 | 约定 |
|----|------|
| 字段来源 | 前端 DynamicQueryForm / 生成页列出全部业务字段；后端 `prepare(entity)` 校验实体属性 + 黑名单，**不必** Service 罗列 allowFields |
| 默认 HTTP | **GET** `/xxx/list`；`conditionsJson` 走 query，可选 Header `X-GP-Conditions-Json` |
| 备用 HTTP | **POST** `/xxx/list`：与 GET 同逻辑，筛选项从 `@RequestBody` 取 |
| 互斥 | 有有效 `params.dq` → 只拼 `DynamicWhere`；无 dq → 扁平字段 `if`（字符串 like、时间 date_format、其余 =） |
| Mapper | 列表与详情共用带表别名的 `selectXxxVo`（如 `sys_user su`）；**不再**保留无别名 `baseSelectVo` / `selectUnionXxxList`；`prepare(entity, alias)` |
| JSON 解析 | 必须用 **`com.alibaba.fastjson2.JSON`**（fastjson 2.0.1 旧包名 `parseArray(Class)` 会抛 `TODO`，导致永不写 dq） |

## valueType → SQL

`conditionsJson` 元素可带 `valueType`（前端传入；否则后端按 Java 属性推断）：

| valueType | 典型 op | SQL 形态 |
|-----------|---------|----------|
| `date` / `datetime` | eq/ne | `date_format(col,'%Y-%m-%d') = date_format(?,…)` |
| `date` / `datetime` | gt/ge/lt/le | `col >/</>=/<= ?` |
| `text`（查询区不用 textarea） | like / notLike | `col like concat('%',?,'%')` |
| `number` / `select` / `switch` / 默认 | eq/ne/… | 直接比较 |

扁平路径（无 dq）同样：`String`→like，`Date`→date_format 等日，其它→`=`。

## 请求约定

- 运算符：`eq` `ne` `gt` `ge` `lt` `le` `like` `notLike` `isNull` `isNotNull`
- Tomcat：`server.tomcat.relaxed-query-chars`；前端 GET 须完整 `encodeURIComponent`
- MyBatis：判断用 `params['dq']`；取值用 `#{params.dq[${index}].value}`

### 排障

```text
DynamicQueryHelper.prepare: … conditionsJson=…
dynamic query ready: … dqSize=N …     ← 成功（SQL 才会有 DynamicWhere）
invalid conditionsJson: TODO …        ← 仍用了旧 fastjson1 API，改 fastjson2
conditionsJson resolved empty …       ← field/op/value 被丢弃
```

## 核心代码

| 路径 | 说明 |
|------|------|
| `DynamicQueryHelper` | `prepare` → `params.dq`；推断/透传 `valueType` |
| `QueryCondition` | field / op / value / valueType / column |
| `mybatis/common/DynamicQueryMapper.xml` | 类型感知 `DynamicWhere` |
| `SysUserController` | GET + POST `/list`，共用 `doUserList` |
| `SysUserMapper.xml` | 单表 + 联表；扁平 / DynamicWhere 互斥 |

## 代码生成

- `controller.ftl`：GET + 精简 POST
- `vue-js.ftl`：`listXxx` GET 默认 + `listXxxPost` 备用
- `mapper-xml.ftl`：仅生成带别名的 `selectXxxVo` + `selectXxxList` / `ById`（不再生成无别名 `baseSelectVo`）
- `service-impl.ftl`：`prepare(entity, tableAlias)` + `applyKeywordColumns`（带别名前缀）
- `mapper.ftl` / `service.ftl`：不再生成 `selectUnion` / `queryUnion`
- `controller.ftl`：`@DataScope(deptAlias, userAlias)` 使用 `tableAlias`
- `vue.ftl` / `vue-antd.ftl`：conditionsJson 带 valueType
- `vue-flat.ftl` / `vue-antd-flat.ftl`：扁平字段 + `searchValue` / 创建时间区间

用户管理已收口为唯一列表 SQL：`selectSysUserList`（`from sys_user su`），已删除 `selectUnionSysUserList`。

### 扁平 searchValue（关键词）

- 与 `conditionsJson` / `params.dq` **无关**；Mapper 片段 `KeywordSearch`。
- Service 须 `DynamicQueryHelper.applyKeywordColumns(entity, "col1", …)`，否则传了关键词也不拼 SQL。
- 用户列表示例：`username` / `nickname` / `phone_number` / `email`（联表加 `su.` 前缀）。

## 查询输入控件

- 按字段 `valueType` 自动选用：text→单行 input；number→数字；select/switch→下拉/开关；date/datetime→日期选择。
- **查询区不使用 textarea**（长文本列也按 text），避免撑破布局。
- **搜索**只带当前条件请求列表，**不得清空输入**；清空/恢复默认行是 **重置** 的职责。
